# Fruit Shop API

REST API магазина фруктов на FastAPI (данные в SQLite) и агент на LangChain, который работает
с этим API по запросам на естественном языке. Отчёт по домашнему заданию — [report.md](report.md).

## Запуск

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
uvicorn app.main:create_app --factory
```

API поднимется на http://127.0.0.1:8000, интерактивная документация (Swagger) — на
http://127.0.0.1:8000/docs.

Настройки читаются из переменных окружения или файла `.env` (пример — [.env.example](.env.example),
сам `.env` не коммитится). Файл базы по умолчанию — `fruits.db` в текущей папке, другой путь
задаётся переменной `FRUIT_SHOP_DB`. База с примерами товаров лежит в репозитории.

## Эндпоинты

| Метод | Путь             | Назначение                  | Ответы        |
|-------|------------------|-----------------------------|---------------|
| POST  | `/products`      | Добавить продукт            | 201, 422      |
| GET   | `/products`      | Список всех продуктов       | 200           |
| GET   | `/products/{id}` | Карточка продукта           | 200, 404      |
| PUT   | `/products/{id}` | Обновить карточку продукта  | 200, 404, 422 |

## Карточка продукта

| Поле          | Тип            | Ограничения                                   |
|---------------|----------------|-----------------------------------------------|
| `id`          | integer        | присваивается сервером                        |
| `name`        | string         | обязательное, 1–100 символов                  |
| `description` | string \| null | до 1000 символов                              |
| `price`       | decimal        | обязательное, больше 0, не более 2 знаков после запятой |
| `quantity`    | integer        | не меньше 0, по умолчанию 0                   |

`price` возвращается строкой (`"129.90"`), чтобы не терять точность. `PUT` заменяет карточку
целиком: не переданные необязательные поля сбрасываются к значениям по умолчанию.

## Пример

```bash
curl -X POST http://127.0.0.1:8000/products \
  -H "Content-Type: application/json" \
  -d '{"name": "Яблоко", "description": "Гренни Смит", "price": "129.90", "quantity": 50}'
```

## Агент (ассистент)

Агент на LangChain с локальной моделью [Ollama](https://ollama.com). Отвечает на вопросы о
товарах магазина и о кофе; с каталогом работает через LangChain tools, которые вызывают
это API по HTTP ([app/tools.py](app/tools.py)). Запустить его можно двумя способами:

- **CLI** (API должно быть запущено в другом терминале; в каждом новом терминале сначала
  активируйте окружение, иначе Windows может запустить заглушку Microsoft Store вместо Python):
  ```powershell
  .venv\Scripts\activate
  python main.py "Какие яблоки у вас есть?"
  python main.py "Поставь малине цену 399 рублей" --role admin
  ```
  Ответ печатается в виде `Status / Action / Data / Errors`, вызовы tools и их результаты
  выводятся в консоль строками `[app.tools] tool …`.
- **HTTP**: `POST /assistant/chat` — ответ в виде JSON с теми же полями (примеры ниже).

Что ещё агент может, зависит от роли:

| `role`           | Возможности |
|------------------|-------------|
| `user` (по умолчанию) | только просмотр каталога |
| `admin`          | ещё добавление товаров и частичное редактирование карточек: меняются только названные поля |

Права ограничены в коде: ассистент для `user` вообще не получает инструментов редактирования.

> ⚠️ Учебный режим: роль берётся из запроса без проверки, поэтому любой клиент может
> указать `admin`. В реальном сервисе роль нужно определять по аутентификации.

Нужна запущенная Ollama со скачанной моделью, поддерживающей инструменты (tools):

```bash
ollama pull gpt-oss
```

| Переменная           | По умолчанию             | Назначение                        |
|----------------------|--------------------------|-----------------------------------|
| `OLLAMA_MODEL`       | `gpt-oss:latest`         | модель Ollama                     |
| `OLLAMA_HOST`        | `http://127.0.0.1:11434` | адрес сервера Ollama              |
| `FRUIT_SHOP_API_URL` | `http://127.0.0.1:8000`  | адрес API, который вызывают tools |

Промпты агента лежат в [prompts/](prompts/).

Запрос к `POST /assistant/chat`:

```json
{"message": "Хочу купить малину"}
{"message": "Поставь малине цену 399 рублей", "role": "admin"}
```

Ответ на первый запрос:

```json
{
  "status": "error",
  "action": "Поиск малины в каталоге",
  "data": [{"id": 4, "name": "Малина", "description": "Свежая, лоток 250 г", "price": "349.00", "quantity": 15}],
  "errors": ["Оформление заказов недоступно"]
}
```

| Поле     | Значение |
|----------|----------|
| `status` | `success` или `error` (`error`, если список `errors` не пуст) |
| `action` | что сделал ассистент |
| `data`   | карточки товаров из каталога (для `admin` — добавленные или изменённые), текст ответа на вопрос о кофе или `null` |
| `errors` | что мешает выполнить запрос; пустой список при успехе |

Модель только выбирает номера товаров, а карточки в `data` сервер получает из API, поэтому цены
и остатки в ответе всегда настоящие. История диалога не хранится: каждый запрос
обрабатывается с нуля.

HTTP-коды: 200; 422 — некорректный запрос; 503 — Ollama не запущена; 502 — ошибка Ollama
(например, модель не скачана). При 502 и 503 тело ответа в том же формате. Первый запрос после
запуска Ollama может идти несколько минут, пока модель загружается в память.
